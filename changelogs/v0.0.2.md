# v0.0.2

Fixes live heart rate monitoring, which could not connect to any device in
v0.0.1, and adds active workout tracking with a live chart.

## Added

**Active tracking with a live chart.** Press Start session with a monitor
connected and the app records the workout, drawing heart rate as it goes. The
line updates at your chosen interval, with the 24-hour Health Connect baseline
drawn behind it as a dashed reference so you can see live effort against your
normal at a glance.

The two data pipelines stay separate and unchanged in character: active
tracking runs entirely off the Bluetooth connection, while the baseline
continues to come from Health Connect.

**A sampling interval, from every 5 seconds to every 5 minutes.** Set it in
Settings under Tracking. It controls how often a point is *recorded* — the big
live BPM number keeps updating as fast as the monitor sends it, whatever the
interval. Shorter intervals give a more detailed chart; longer ones cover a long
workout without a dense, unreadable line.

Each recorded point is the **average** of that interval's readings, not a single
snapshot, and carries the interval's high and low. The chart shades that range
behind the line — so a steady 118 and a swing between 90 and 150 look different,
where an average alone would make them identical.

The interval is locked while a session is recording, since changing cadence
partway would make the chart's spacing inconsistent with itself.

**A History tab.** Past sessions, newest first, with duration, average, and max.
Tap one for its full chart and summary, or to delete it. Sessions that never
recorded a point are left out rather than shown as empty rows.

**Play/stop iconography** on the existing Start session button. It remains the
single control for starting a recording.

## Fixed

**Connecting to a heart rate strap now works.** Every connection attempt
previously failed with `Service 0000180d-0000-1000-8000-00805f9b34fb for device
? not found`, leaving the app stuck on "Disconnected". Reported on a Google
Fitbit Air; it affected all devices.

The cause was in the app, not the hardware. `connectToDevice` connected and
discovered the peripheral's services correctly — then discarded the connection
object it had just set up. `subscribeHeartRate` opened a *second* connection and
tried to read the heart rate characteristic from that one, which had never had
service discovery run on it. react-native-ble-plx scopes discovery to the
specific connection object, so the lookup failed every time.

Connecting and subscribing now share one connection, discovered once.

## Added

**A clearer message when a watch hides its heart rate service.** Some wearables
advertise the standard Heart Rate Service but only actually serve it while an
explicit "broadcast heart rate" or workout mode is switched on. That case now
says so, and tells you to enable that mode and reconnect, instead of showing a
raw Bluetooth error.

**A clearer message when subscribing without a connection**, rather than failing
silently.

## Under the hood

- `subscribeHeartRate` no longer takes a device id and no longer connects.
  Connecting is `connectToDevice`'s job; a subscribe that quietly opened its own
  connection is what created two divergent connection objects. Its disposer is
  now synchronous instead of chaining off a pending promise.
- The retained connection is cleared on both explicit disconnect and unexpected
  peripheral dropout, so a later subscribe cannot monitor a dead handle.
- The `react-native-ble-plx` test mock now enforces two of the real library's
  preconditions it previously ignored: monitoring requires discovery on the same
  instance, and connections are counted. The old mock modelled a happy path the
  library does not offer, which is how a connect flow that cannot work on
  hardware passed 93 tests. Replaying the old flow against the new mock
  reproduces the exact error above.
- 15 new tests covering the BLE façade, which previously had none — single
  connect per session, discovery before monitor, missing-service rejection,
  disposal, and teardown clearing the retained device.

### Active tracking

- Schema v2. `session_readings` gains `hr_min`/`hr_max`; `sessions` gains
  `interval_ms`. Existing rows backfill to `hr_min = hr_max = hr_value`, which
  is true rather than merely convenient — they were written one per
  notification, so the sample *was* the whole interval. `interval_ms` stays NULL
  for those sessions: they had no fixed cadence, and inventing one would
  misrepresent their x-axis.
- The cadence is recorded per session rather than read from settings at render
  time, so a past chart keeps the spacing it was captured with after the
  preference changes.
- Chart geometry lives in `src/utils/chart.ts` as pure functions — domain,
  scales, polyline, range band, ticks, downsampling. An inverted axis or a
  clipped domain is invisible in a snapshot and obvious in an assertion, so the
  scaling is kept out of the component and tested directly.
- The y-domain includes the baseline, so the reference line cannot silently
  clip and be misread as off-scale. It is never anchored to zero: heart rate
  occupies a narrow band far from it, and a zero-based axis flattens every
  session into one line across the top.
- An interval that received no readings records nothing rather than a zero — a
  dropped strap is a gap, not a heart rate of zero. The trailing partial
  interval is flushed on stop, so ending a session no longer discards up to one
  interval of data.
- `DARK.baseline` moves `#60A5FA` → `#3B82F6`. The old value sits at OKLCH
  L 0.714, outside the dark-mode lightness band; the replacement passes the
  band, chroma floor, colour-vision separation from the live line (ΔE 26.7
  protan), and 3:1 contrast against the dark surface. Computed with a
  validator, not eyeballed.
- One new dependency: `react-native-svg`, at the version Expo pins for SDK 55.
- No touch tooltip on the chart. Hover doesn't exist on a phone, and a scrub
  gesture over a live-updating series is separate design work; the live BPM
  card already shows the value a tooltip would report.

149 unit tests pass (was 93); typecheck is clean.
