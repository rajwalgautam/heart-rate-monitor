# v0.0.1

First release. Initial implementation of the heart rate monitor.

Builds the app described in `implementation.md`: an offline-first Android monitor showing live BLE heart rate against a 24-hour Health Connect baseline. Structure, conventions, and infra mirror `its-a-rock`.

This release also adds `implementation.md` and `prompt.md` themselves — they were untracked on `main`.

## Approach

**Pure logic before native wrappers.** The plan originally ordered the service façades ahead of the parsing/baseline math; that is inverted here. Both pure modules are fully testable with no device and they define the interface each wrapper has to satisfy, so they were built and covered first. Neither imports a native module.

- **BLE parsing** (`src/ble/utils.ts`) — Heart Rate Measurement (`0x2A37`): the bit-0 format flag, little-endian 16-bit payload, and a hand-rolled base64 decoder so the same code path runs under Hermes and under Node in tests with no polyfill and no assumption about available globals.
- **Baseline math** (`src/healthconnect/utils.ts`) — flattens Health Connect's nested `samples` arrays before averaging. Averaging per record instead of per sample produces a plausible-looking wrong number, so there is a test that fails specifically on that mistake.

**Façades keep the libraries contained.** Nothing outside `src/ble/` and `src/healthconnect/` imports `react-native-ble-plx` or `react-native-health-connect`. Every scan/subscribe returns a disposer, which is what makes the teardown contract enforceable rather than aspirational — a caller cannot start something it has no way to stop.

## Decisions implemented

| | Decision | Where |
|---|---|---|
| **D1** | `react-native-ble-plx` over `ble-manager` — ships its own Expo plugin for the Android 12+ permission manifest | `app.json`, `src/ble/BleManager.ts` |
| **D2** | 30s foreground poll + debounced on-demand refresh; dedupe on unchanged sample timestamp; rate-limit backoff that keeps the last value **visible and marked stale** rather than blanking the card | `src/store/useBaselineStore.ts` |
| **D3** | `session_readings` written live; `avg_hr`/`max_hr` from an in-memory accumulator, so the summary survives a failed insert | `src/store/useHeartRateStore.ts` |
| **D4** | Health Connect permissions as real work — rationale activity, API 34+ alias, package-visibility queries, plus a degraded path | `plugins/withHealthConnect.js` |

D2's dedupe exists because Fitbit writes to Health Connect every 1–5 minutes, so a 30s poll oversamples the source 2–10× and most reads are byte-identical.

## Verification

```
npx tsc --noEmit          clean
npx jest                  93 passed, 12 skipped
npx expo config           resolves with all 5 plugins
```

The plugin output was checked rather than assumed — `ACTION_SHOW_PERMISSIONS_RATIONALE`, `ViewPermissionUsageActivity`, the `com.google.android.apps.healthdata` queries entry, `READ_HEART_RATE`, and `neverForLocation` are all confirmed present in the introspected manifest.

## What is *not* done

Stated plainly so nothing here reads as more finished than it is:

- **No device run.** Gates 3 and 5 in the plan need real hardware. Everything below the native boundary is tested; the boundary itself is not.
- **Component tests are `describe.skip`-ped.** RN 0.83 new-arch host components render to a null stub under jest-expo 55, so every RNTL query finds nothing. This is a pre-existing environment limitation that `its-a-rock` and `water-tracker` already document and skip — not something introduced here. The specs are written in full and should pass unchanged once it is fixed; `__tests__/components/harness.test.tsx` is the canary to un-skip first. The presentation logic those cards display is factored into `src/utils/format.ts` and tested there.
- **The signing path is unproven until this build.** The keystore and the four repository secrets are now in place, but nothing has verified end-to-end that the stored `KEYSTORE_BASE64` decodes to the right keystore — GitHub secrets are write-only, so only a real build proves it. This release *is* that verification. Confirm the signature on the published APK with `keytool -printcert -jarfile app-release.apk`.

## Follow-ups worth considering

- `minSdkVersion` is raised to 26 for Health Connect via `withAndroidCompileSdk.js`. Worth confirming against your target devices.
- `isRateLimitError` matches on message text because Health Connect surfaces quota exhaustion as a string, not a typed error. A false negative just takes the generic error path, which is also non-fatal.
